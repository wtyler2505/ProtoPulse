## Tech Stack

- **Runtime**: Node.js (Express 5, `tsx` for dev). Desktop shell via **Tauri v2** (Rust).
- **Framework**: React 19.2 + Vite 7.1 (SPA, no SSR)
- **Language**: TypeScript 5.6.3 (server + client + shared)
- **Desktop**: Tauri v2 (`@tauri-apps/api` 2.10) — migration in progress (web/cloud stays Express; desktop-privileged work moves to typed Rust commands)
- **Styling**: Tailwind v4 + shadcn/ui (New York dark theme)
- **Testing**: Vitest 4 + happy-dom 20 + @testing-library/react; Playwright for E2E/a11y
- **Linting**: ESLint (flat config, strictTypeChecked) + Prettier
- **Key Dependencies**:
  - `drizzle-orm` 0.45 + `pg` — PostgreSQL ORM with Zod schema integration (51 tables)
  - `@tanstack/react-query` 5.99 — server state (no Redux/Zustand)
  - `@google/genai` 1.43 + `genkit` 1.34 + `openai` 6.38 — **dual AI provider: Gemini (primary) + OpenAI**
  - `three` 0.184 — 3D board viewer
  - `wouter` 3.3 — lightweight client routing
  - `helmet` + `express-rate-limit` — security middleware

## Architecture in 30 Seconds

All-in-one browser-based EDA suite for makers, hobbyists, and anyone working with microcontrollers, electronics, robotics, or embedded systems. Think TinkerCad + Fritzing + KiCad + Arduino IDE unified with AI. Born from the OmniTrek Nexus rover project; now a universal tool.

Monolithic Express server serves both the API and the Vite-built SPA. AI chat exposes ~117 AI tools (across 22 tool modules) that directly manipulate project state (add nodes, generate architectures, manage BOM, run DRC, circuit ops, exports). Multi-format export: KiCad, Eagle, SPICE, Gerber, drill, pick-and-place, design report, FMEA, firmware scaffold, PDF. All client state flows through a single `ProjectProvider` React context backed by React Query mutations. A **Tauri v2 desktop build** is being layered on top (typed Rust commands for filesystem, store, serial, deep-link).

## Non-Obvious Conventions

- Soft deletes on `projects`, `architecture_nodes`, `architecture_edges`, `bom_items` — always filter `isNull(deletedAt)`
- Auth uses `X-Session-Id` header, not cookies
- Node IDs use `crypto.randomUUID()`, not `Date.now()`
- AI providers are **`gemini` | `openai`** (+ fab-house providers `jlcpcb`/`pcbway`/`oshpark`/`google_workspace` for API keys) — Anthropic/Claude was removed
- Collaboration uses a **server-assigned monotonic Lamport clock**: the later-processed op gets the higher timestamp and wins LWW (`server/collaboration.ts:494-508`)
- `@/*` path alias maps to `client/src/*`, `@shared/*` maps to `shared/`
- ESLint enforces `import type` for type-only imports
- Tauri typed commands take JSON-stringified `String` params, not `serde_json::Value` (specta recurses infinitely on `Value`)
- Client tests: per-file `vi.stubGlobal('localStorage'/'fetch', ...)` at module level — `client/src/test-setup.ts` is deliberately minimal (no global stubs / no `unstubAllGlobals`)

## Architectural Decisions

- **Tauri path C topology**: Express stays for web/cloud; desktop-privileged work (FS, store, serial, deep-link) moves to typed Rust commands. See `docs/decisions/2026-05-10-adr-tauri-runtime-topology.md`.
- **Express 5 (not Next.js)**: SPA with separate API; no SSR needed for a tool app
- **React Query over Redux**: server state only
- **Gemini-primary AI**: default `aiProvider: 'gemini'`, model `gemini-3.1-pro-preview-customtools`; OpenAI as alternative
- **Monolithic `ProjectProvider`**: acknowledged tech debt — works for the current scope
- **Vitest workspace projects**: separate `client` (happy-dom) / `server`/`shared`/`electron`/`scripts` (node) environments

## Gotchas

- Run DB migrations before dev (`npm run db:push` / `db:migrate`); `migration-drift` test fails loudly when `shared/schema.ts` table count drifts from migrations
- `npm run check` runs `design:check` (token drift) THEN `tsc` with 16GB heap — both must pass
- Tests need a large heap: `NODE_OPTIONS=--max-old-space-size=8192` (set in the `test` script)
- A repo hook forces test commands to run in the background — foreground `vitest`/`playwright` runs are blocked
- happy-dom has no `Worker` global — view tests that use workers must stub it locally (not in the shared setup)
